An integration is anything outside your project's code that the agent, or the app it builds, can use: an app such as Gmail or Slack, a service built into every session such as PostgreSQL, or an MCP server that adds tools. The **Integrations** page holds all of them in one catalog, and anything you connect there works in every session you own. To sign in to an app, see [Connect an app](/integrations/connect-apps). For hosted or local MCP servers, see [MCP servers](/integrations/mcp-servers). To call your connections from the code the agent writes, see [Use integrations in your app](/integrations/in-your-app).

## What counts as an integration?

Each card names its kind with a badge at its foot. Built-in services land in the agent's environment; connectors and MCP servers reach it as tools.

| Kind (badge) | What it is | How you connect it | For example |
| --- | --- | --- | --- |
| **Connector** | A ready-made link to an outside app. Each function, such as "Send email", becomes a tool. | **Sign in** or **Connect** under **Connectors → Apps**. | Gmail, Google Calendar, Slack, Jira |
| **Built in** | A service in every session's machine. | Nothing to connect. The agent switches it on. | PostgreSQL, User sign-in |
| **Remote MCP** | An MCP server hosted on the web, reached through Alpha. | **Sign in** or **Connect** under **MCPs → Remote**, or add one by its address. | Stripe, Notion, Sentry, Linear |
| **Local MCP** | An MCP server that runs as a command inside every session's machine. | **Install** under **MCPs → Local**, or add a command. | Context7, Memory, Sequential thinking |

Connector and remote MCP sign-ins never enter a session. Sessions and apps hold only a per-session key, never your password or the app's own token.

<Note>
If you don't see an app or MCP server you expected, it isn't turned on for your Alpha. Your admin chooses which apps and hosted MCP servers the catalog offers.
</Note>

## Browse the catalog

Click **Integrations** in the sidebar to open the **Integrations** page. The row's badge counts what you have connected. Under the cover, the lede reads "Sign in once and build with it across your sessions, apps and agents — 2 connected." Click a card to open its detail as a dialog over the page: what it gives the agent and how to connect it.

The page has three tabs:

| Tab | Sub-tabs |
| --- | --- |
| **Connectors** | **Apps** (outside apps) and **Built in**, each with a count, and **Refresh** at the right |
| **MCPs** | **Remote** and **Local**, each with a count, with **Refresh** and **Add server** at the right |
| **Connected** | None. It lists everything that is on, and its label shows how many, such as **Connected · 2**. |

| Control | What it does |
| --- | --- |
| Search | Searches every tab at once, whichever tab is open. While you search, the sub-tabs hide and the results mix apps, built-ins and servers. |
| **All auth** | Narrows the cards to **OAuth**, **API key** or **No auth**. |
| **All categories** | Narrows the cards to one category on the open tab, such as "Business tools" or "Development". |
| **Refresh** | Loads the latest list of apps and MCP servers. |

Cards are sorted A to Z.

### Open the catalog as a dialog

Some ways in open the same catalog as a large dialog over whatever you are doing, so you don't leave your session:

| Way in | What opens |
| --- | --- |
| [`/integrations`](/reference/slash-commands) in a session or on the home screen | The catalog dialog. `/integrations gmail` opens it at that entry. |
| **Connect** on a card the agent posts in the transcript | Only the entry the agent asked for, with its reason. **Browse all integrations →** opens the rest. See [When the agent asks you to connect](/integrations/connect-apps#when-the-agent-asks-you-to-connect). |
| **Manage servers** on the home screen's `/mcp` card | The catalog dialog. See [MCP servers](/integrations/mcp-servers#check-what-every-session-gets). |

The dialog works like the page, with a few differences: its first sub-tab is called **Connectors** rather than **Apps**, each tab has its own **Connected** sub-tab, the search covers only the open tab, and a card's detail opens in a panel at the right instead of a dialog.

## Read a card

Every card tells you what a thing is, how it signs in and whether it is on.

{/* screenshot to capture: /images/integrations/integrations-card-anatomy.png — One card, with its six parts numbered: logo, Verified, category, action or status, type badge and auth badge. */}

1. **Logo.** A server with no mark of its own shows the MCP glyph. Once the thing is on, a green dot sits on the logo.
2. **Verified.** The check beside the name means Alpha curated it. Servers you add yourself don't get the check.
3. **Category.** The line under the name, such as "Business tools" or "Development".
4. **Action or status.** At the top right. See the table below.
5. **Type badge.** At the foot: **Connector**, **Built in**, **Remote MCP** or **Local MCP**.
6. **Auth badge.** Beside the type: **OAuth** (sign in with the app's own account), **API key** (paste a key or credentials) or **No auth** (one click). Built-ins have none.

| Corner reads | Meaning | Click it to |
| --- | --- | --- |
| **Sign in** | Not connected; uses OAuth. | Open the app's sign-in in a popup, or open its detail first when it needs more from you. |
| **Connect** | Not connected; takes a key, extra fields or nothing. | Connect at once, or fill in its form in the detail. |
| **Install** | A curated local MCP server. | Install it in every session you own. |
| **Disconnected** | A remote server whose access was revoked. | Open its detail to remove it and add it again. |
| Pill **Active**, green dot | Connected, or installed and on. | Open its detail to test, disconnect or switch it off. |
| Pill **Off**, grey dot | A local server switched off. | Open its detail to switch it on. |

When a remote server's sign-in has expired and can't be refreshed, its detail reads "Sign in again". Built-in cards show nothing in the corner, because they are always there.

## Use the built-in services

**Connectors → Built in** lists the six services every session's machine already has. The agent switches each one on when your project needs it.

<Frame caption="Built in: six services, with no sign-in and no button.">
  <img src="/images/integrations/integrations-page-builtin.png" alt="The Integrations page on the Connectors tab, under the cover and its lede, with the sub-tabs Apps and Built in 6 (selected), the All auth and All categories dropdowns and a Refresh button. Six cards sit in a two-column grid, sorted A to Z: Alpha tools, GitHub, Headless browser, Image generation, PostgreSQL and User sign-in. Each card shows its logo, its name with a Verified check, a category line under the name, a one-line description and a grey Built in badge at its foot. No card shows a button or a status pill." />
</Frame>

| Service | What the agent gets | How it's switched on |
| --- | --- | --- |
| [**PostgreSQL**](/workspace/database) | The session's own database: `DATABASE_URL` and the `PG*` variables. | The agent starts it when your app stores data; the **Database** tab opens. |
| [**User sign-in**](/workspace/app-sign-in) | Google or email accounts for your app's users, with the sign-in settings already in the app's environment. | The agent turns it on when your app needs accounts; the **Auth** tab opens. |
| **Image generation** | Hero images, icons and illustrations from a prompt, saved into the project. | The agent runs Alpha's image generator. No variables. |
| **Headless browser** | Its own Chromium, to check its pages and read the web. | Always on, as browser tools. |
| [**Alpha tools**](/integrations/in-your-app) | Everything you connected, callable from the agent, your app and its agents, through the session's key. | Always set, in every shell and published app. |
| [**GitHub**](/github/connect) | An authenticated `git` and `gh`: `GITHUB_TOKEN`, `GH_TOKEN`. | You connect it in a session's **GitHub** tab (**+** → **GitHub**), not here. |

Click a built-in to see what the agent works from: a **Built into Alpha** box, a **What the agent gets** list of its variables for those that set any, and a collapsed **What the agent will follow** section. Expand it to read, word for word, the recipe the agent follows for that service.

## Where does a connection reach?

A connection belongs to your account, not to one session. Sign in to Gmail once and every session you own can use it.

| Where | How it reaches your connections |
| --- | --- |
| The agent, in every session you own | As tools in its tool list. |
| Your app in the [Preview](/workspace/preview) | Through the session's key, already in its environment. |
| Apps you [publish](/publish/publish-your-app) | The same key, set on the published app. |
| An app you export and run elsewhere | Paste the two lines from the session's key into its `.env`. |

Connections belong to your account alone. Other people's sessions never get them, even when you [share a session](/sharing) with them.

### When do changes take effect?

Connecting, disconnecting or revoking something updates every running session of yours. If the agent is mid-turn, the change waits for that turn to end, so the new tools arrive with your next message.

### Check what's on

The **Connected** tab lists every connector you signed in to and every MCP server that is on, your own servers included. Built-in services never appear there. Its count matches the badge on the sidebar's **Integrations** row.

{/* screenshot to capture: /images/integrations/integrations-page-connected.png — Connected gathers connectors and MCP servers of both kinds in one list. */}

With nothing on, the tab reads "Nothing connected yet — sign in to a connector or install an MCP server."

### See what a session used

Once the agent in a session has called a connected service, such as Gmail, GitHub or a remote MCP server, the service's logo appears in the session's header, beside its title. Hover over a logo to read its name, such as "gmail · used in this session". The row grows as the agent reaches for more services, so you can tell at a glance what a session touched.

## What if a service isn't listed?

It still works. Search for it, and when nothing matches the catalog says so: "A service that isn't here still works as a plain secret — the agent will name the variable."

Ask the agent to use the service. When it needs a key it posts a card in the transcript, such as "The agent needs `HARBOR_WEATHER_API_KEY`", with an **Add HARBOR_WEATHER_API_KEY** button that saves the key as a [secret](/secrets). The agent then reads it as an environment variable. If the service offers an MCP server, you can also add it yourself under **MCPs → Add server**, as described in [MCP servers](/integrations/mcp-servers).

<Warning>
Never paste a key into the composer. Anything typed in the composer lands in the session's transcript, and Alpha warns you when your message looks like it holds one. Add keys under [Secrets](/secrets) or connect the app here.
</Warning>
