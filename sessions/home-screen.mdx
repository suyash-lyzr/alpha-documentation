The home screen is where you set up a session before it exists. Nothing runs behind it yet, and no machine has started. Your first prompt creates the session and starts its machine, and [What happens when you start a session](/sessions/start-a-session) follows it from there. To go back to work you already started, find it in the [sidebar](/sessions/organize).

## Open the home screen

Alpha opens on the home screen. To come back to it from a session, do one of these:

| Way in | Where |
| --- | --- |
| **New session** | The first row of the sidebar |
| The Alpha logo | The top of the sidebar (tooltip "Home") |
| <kbd>⌘</kbd><kbd>⇧</kbd><kbd>O</kbd> | Anywhere in Alpha. Use Ctrl instead of ⌘ on Windows and Linux. |

Opening the home screen creates nothing, so you can leave it again without a stray empty session in your list. The composer has focus from the start.

## Set up the next session

The composer's bottom row sets up the session your next prompt will start. On the left are the **+** menu, the model chip and the effort chip. On the right, before Send, are the **Build** or **Plan** chip and the microphone.

| Control | Sets | Remembered for later sessions? |
| --- | --- | --- |
| **+** | Files, the machine, repositories, a skill or a secret set for the session. See the next table. | See the next table |
| Model chip | The model, named on the chip after the agent's mark, such as **Opus 5.5**. Its popover lists each model with a short tag, such as "fastest", and a check on the one in use. When your Alpha offers both agents, a **Codex** / **Claude Code** switch sits at the top of the popover. The session keeps its agent for life, and switching resets the model and effort to the new agent's defaults. | Yes, in this browser |
| Effort chip | The reasoning effort, such as **xhigh**. Its **Reasoning effort** popover lists every effort the agent offers. Efforts the chosen model doesn't offer are dimmed. The chip hides when the model has no effort levels. | Yes, in this browser |
| **Build** / **Plan** | **Build** ("Makes changes directly") or **Plan** ("Asks, then proposes a plan", see [Plan mode](/chat/plan-mode)). The chip shows the one in force. <kbd>⇧</kbd><kbd>Tab</kbd> switches it from the composer. | Yes, in this browser |

The **+** menu ("Add files, a machine, repos, a skill or a secret set") holds everything else the session starts with.

| Item | What it does | Remembered for later sessions? |
| --- | --- | --- |
| **Add files** | Opens your file picker. You can also drop files onto the composer. Files wait in the browser until the session exists, then upload to `uploads/` in its workspace. | No |
| **Machine** | Shows **blank** or the setup you picked. Opens the **Setup** popover: **Blank machine** (marked **default**), then your [setups](/sessions/setups) and the ones shared with you. A setup marked **building** or **not built** can't be picked yet. **Manage setups →** opens the **Setups** page. | No. Every new session starts on the blank machine until you pick a setup. |
| **GitHub repos** | Shows how many you've staged. Opens the **Repositories** popover: GitHub repositories to clone before the agent starts, each with an optional branch. The limit is [{reposMax}](/reference/limits), and a setup's repositories count toward it. | No |
| **Skills** | Opens the composer's skill list, as typing `$` does in a Codex draft or `/` in a Claude Code draft. | Not a setting |
| **Secret set** | Shows **none** or the set you picked. Its submenu lists **None** and your own [secret sets](/secrets#secret-sets), with "N required" beside a set that's missing values, then **Create a secret set**. | No |

A machine, repositories or a secret set you pick sit in a tray tucked under the composer, one chip each. Rest the pointer on a chip to read what it does, such as "The machine this session starts on" or "Cloned into the session's workspace before the agent starts". Click a chip to open its picker again, or its **×** to take it off.

The machine, repositories and secret set are deliberately not remembered, so something you picked for one task can't end up in an unrelated session later. If you connect GitHub from the **Repositories** popover, Alpha takes you to github.com and back, and your typed prompt, staged repos and name are all still there. [Connect GitHub and add repositories](/github/connect) covers the popover in full. [Choose the agent and model](/chat/agents-and-models) explains the models and efforts.

There's no permissions chip. Every new session runs with full access inside its own machine. The agent installs packages and runs commands without asking, and nothing it does reaches your other sessions. If you type `/permissions`, Alpha answers in a banner: "/permissions isn't offered — every session runs with full access."

<Note>
If the model popover has no **Codex** / **Claude Code** switch, or you don't see the microphone, your Alpha isn't set up to offer both agents or voice input. Without the switch, sessions run the one agent your Alpha provides.
</Note>

## Switch between light and dark

The button at the top right of the home screen switches Alpha between its light and dark themes. Its tooltip names the theme it switches to: "Light mode" or "Dark mode". The **Theme** setting under **Account menu → Settings → Appearance** also offers **System**, which follows your computer's light or dark mode and is the default. The choice is kept on this device only. See [Your account and settings](/account/your-account#change-your-settings).

## Start from a suggestion

The seven chips under the composer are starting points: **Apps**, **Agents**, **Decks & docs**, **Images & video**, **Data**, **Automations** and **Research**. Click one and its list opens over the row, so the page doesn't move. Each row is a short line such as "Take bookings for my small business" or "Get a morning digest of AI news".

| You do | What happens |
| --- | --- |
| Hover a row, or reach it with the keyboard | The composer shows the row's full prompt as a preview |
| Click a row | The full prompt fills the composer, with the caret at the end. Nothing is sent. |
| Press <kbd>⌘</kbd><kbd>Z</kbd> after a pick | The text you had typed before comes back |
| Press <kbd>Esc</kbd>, click **×** or click outside | The list closes |

A suggestion is a first draft. Edit it to match your project before you send it, for example by naming your sailing school and its class types.

## Use commands before the session exists

Type `/` in the home composer to open the same command palette you get inside a session. Here it acts on the session about to start. Most commands change a chip or open its popover. A few start the session at once, with the command as its first message.

<Frame caption="The palette on the home screen acts on the next session.">
  <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@d3746aff596b13cbfd84695ae54a27a24310522f/images/sessions/home-slash-palette.webp" alt="The home composer with a single slash typed and the command palette open above it. Each row shows an icon, the command and a description: /model, choose what model and reasoning effort to use; /skills, list skills the agent can use ($name mentions them); /review, review my current changes and find issues; /rename, rename this session; /new, start a new session; /delete, permanently delete this session; /fork, fork this session, with a description saying it copies the machine, files and conversation; /init, create an AGENTS.md file with instructions for the agent; /compact, summarize conversation to prevent hitting the context limit. The /model row is highlighted. The footer reads ↑↓ navigate, ↵ select, esc dismiss and, at the right, commands. The send button below is lit." />
</Frame>

| Command | On the home screen | Starts the session? |
| --- | --- | --- |
| `/harness`, `/harness codex`, `/harness claude` | Bare, opens the model chip's popover, with the **Codex** / **Claude Code** switch at its top. With a name, switches the agent. Listed only when your Alpha offers both agents. | No |
| `/model` | Opens the model chip's popover. In a Claude Code draft, `/model <name>` sets the model directly. | No |
| `/effort <level>` | Claude Code drafts only. Sets the effort: `low`, `medium`, `high`, `xhigh`, `max` or `ultracode`. `/effort auto` goes back to the model's own. Bare `/effort` opens the model chip's popover; to pick an effort from a list, use the effort chip. | No |
| `/plan`, `/plan on`, `/plan off` | Switches plan mode: bare `/plan` turns it on if it's off and off if it's on. The chip shows **Plan** or **Build**. | No |
| `/plan <task>` | Opens the session in plan mode, with the task as its first message | Yes |
| `/rename <name>` | Names the session up front, up to 80 characters, and adds a name chip. Bare `/rename` opens **Name the session**. | No |
| `/init` | The agent writes `AGENTS.md` (Codex) or `CLAUDE.md` (Claude Code), the instructions file for your project | Yes |
| `/review <instructions>` | Opens the session as a code review. Bare `/review` opens **Start a review**. | Yes |
| `/status` | Shows the **Next session** card | No |
| `/skills`, `/mcp` | Cards listing the skills and MCP servers every new session gets | No |
| `/usage`, `/integrations` | Open the Usage page or Integrations | No |
| `/new` | Clears the composer, including attached files, and takes off the machine, repositories, secret set and name you picked. The remembered agent, model, effort and mode stay. | No |

With a repository staged, `/review against main` or `/init` is a complete first message. You don't need a prompt as well. In a Claude Code draft, Claude Code's own commands and your skills also start the session at once.

Commands that need a running session say so instead of doing anything:

| Command | Alpha says |
| --- | --- |
| `/fork` | "Nothing to fork yet — this session begins with your first prompt." |
| `/compact` | "Nothing to compact yet — the conversation begins with your first prompt." |
| `/diff` | "No workspace yet — the machine starts with your first prompt." |
| `/agents` (Claude Code drafts) | "The sub-agents are listed once the session's agent has started — run /agents there." |
| `/delete` | "Nothing to delete — no session has been started yet." |

<Tip>
Not sure what the next session will start with? Type `/status` before you send.
</Tip>

The **Next session** card lists **Name**, **Agent**, **Model**, **Permissions**, **Mode**, **Setup**, **Repos**, **Files**, **GitHub**, **Integrations** and **Secrets**. The **Agent** row appears only when your Alpha offers both agents. Its footer reads "The session your next prompt starts. Nothing is running yet; token usage appears once it is." Each card closes with the **×** in its corner. Every command is listed in [Slash commands](/reference/slash-commands).

## Mention files and skills before the session exists

The workspace doesn't exist yet, so `@` and `$` list what it will start with.

| Type | Lists |
| --- | --- |
| `@` | The files you've attached, as `uploads/…`, and every file in your setup's and staged repositories, read from GitHub. With neither, the list says "Attach files or stage a repository to mention their files here". |
| `@session:` and a word | Your other sessions that match the word |
| `@artifact:` and a word | Your [artifacts](/artifacts) and those shared with you. Before the first turn, Alpha copies a tagged artifact's files into the new session's workspace. |
| `$` | The skills every new session gets. Codex drafts only. |
| `/` in a Claude Code draft | Your skills appear among the commands. Claude Code runs a skill as `/name`. |

Picking a file inserts `@path`, so the agent knows exactly which file you mean from its first turn. The [composer](/chat/composer) page covers mentions inside a running session, including `@session:` for your other sessions. [Skills](/skills/overview) explains what a skill adds.

## What happens to my unsent prompt?

Alpha keeps your unsent text in this browser, so a reload or a closed tab loses nothing you typed.

| Event | Your draft |
| --- | --- |
| You reload or close the tab | The text is kept. Attached files are not. |
| You send it | It's cleared and becomes the session's first message |
| Creating the session fails | Your prompt and files go back into the composer, with the error in a banner at the top |
| You sign out of Alpha | Every unsent draft in this browser is cleared |
| The text contains something that looks like a key | It isn't saved to the browser at all |

<Warning>
Anything you send from the composer lands in the session's transcript, keys included. If you paste something shaped like a key, the composer warns you: "Keys typed here land in the transcript — add it under Secrets instead, and the agent gets it as an environment variable." [Secrets](/secrets) shows how.
</Warning>
