Every session runs on a private Linux machine of its own. This page covers what's installed on it, where your files live, and the environment your app and the agent's commands can read. For when the machine sleeps, wakes or resets, see [Sleep, wake and reset](/sessions/machines). To type commands into it yourself, open the [Shell](/workspace/shell).

## What's installed on every machine

A new machine starts with the tools below. A [setup](/sessions/setups) starts with the same tools, plus your repositories and dependencies already in place.

| Part | What you get |
| --- | --- |
| Operating system | Ubuntu 24.04 |
| The agents | Codex and Claude Code. Each session runs the one you picked when you started it. See [Choose the agent and model](/chat/agents-and-models). |
| JavaScript | Node.js 22 with `npm`, and Bun |
| Python | Python 3.12 with `venv`, `pip` and `uv` |
| Database | PostgreSQL 16, installed but switched off until your app needs it. See [Your session's database](/workspace/database). |
| Browser | A headless Chromium the agent uses to open and check its own pages |
| Command-line tools | `git`, `gh`, `ripgrep`, `jq`, `curl`, `unzip`, `nano`, `less`, `sudo` |
| Documents | A slide exporter for PowerPoint and PDF, and a LaTeX engine that builds `.tex` files for the PDF viewer. See [File viewers](/workspace/file-viewers). |
| Images | Image generation the agent can use without asking you for a key |
| Disk | {disk}. See [Limits](/reference/limits). |

The agent works as an ordinary Linux account named `agent`, with `sudo` and no password. So `sudo apt-get install` and global `npm` installs work, and whatever it installs stays on the machine through sleep and wake. A reset, which an admin does, throws it away and starts a fresh machine, from the session's setup if it has one. See [Reset the session's machine](/sessions/machines#reset-the-sessions-machine).

## Where do my files live?

Your project is `/workspace`. It's the folder the agent starts in, the root of the [file tree](/workspace/files), and the home folder in the Shell.

| Path | What's there |
| --- | --- |
| `/workspace` | Your project. Everything the agent builds goes here. |
| `/workspace/uploads` | Files you attach in the composer, up to {uploadMax} each ([Limits](/reference/limits)). They land as soon as you add them, before you send. |
| `/workspace/<repo>` | Each repository you add, cloned under its own name. If the name is taken, it becomes `/workspace/<owner>-<repo>`. See [Connect GitHub and add repositories](/github/connect). |

Screenshots the agent's browser takes are kept outside your project, so they don't end up in your repositories. Ask the agent to copy one into `/workspace` if you want it.

Alpha's own files on the machine stay out of your project and out of the Shell's view. Your secrets reach the environment as variables, so you never need to look for them on disk.

## Which environment variables are set?

Nothing is set ahead of time. A session without a database has no `DATABASE_URL`, and an app without sign-in has no sign-in settings. Each value appears the moment its service comes on.

| Variable | Set when | What it holds |
| --- | --- | --- |
| `DATABASE_URL` | The session's database is on | The connection string for the session's PostgreSQL. Apps should read this rather than hard-code one. |
| `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE` | The session's database is on | The same connection, split up, so `psql` connects with no arguments |
| Your app's sign-in settings | App sign-in is on | What your app needs to sign users in, already filled in. See [Add sign-in to your app](/workspace/app-sign-in). |
| Your app's key for connected apps | Integrations are turned on for your Alpha | The address and key your app uses to call your connected apps and MCP servers. See [Use integrations in your app](/integrations/in-your-app). |
| `GITHUB_TOKEN`, `GH_TOKEN` | You've connected GitHub | A token for `git`, `gh` and anything else that talks to GitHub. See [Connect GitHub and add repositories](/github/connect). |
| `GIT_COMMITTER_NAME`, `GIT_COMMITTER_EMAIL` | You've connected GitHub | Alpha's GitHub app as the committer. You stay the author of every commit. |
| `OPENAI_BASE_URL`, `OPENROUTER_BASE_URL` | You've added an `OPENAI_API_KEY` or `OPENROUTER_API_KEY` secret without its base URL | The provider's public address, so code that reads the pair works without you pasting a URL |
| `PORT` | The agent started a server on a port | The port that server was asked to listen on |
| Your secrets | You've added them | Every [global and session secret](/secrets), under the name you gave it |

Your secrets win over every built-in value, so a secret named `DATABASE_URL` or `GITHUB_TOKEN` replaces the one Alpha sets. Between secrets, a session secret beats a global one, and either beats the token from a GitHub connection. A few names are reserved and can't be used for secrets, so the sign-in and integration settings can't be replaced by accident.

Every command the agent runs, every server it starts and every new Shell read these variables as they start. A change reaches the agent's next command without a restart. A Shell that was already open keeps what it had, so click **Restart shell** to pick up a new secret or a database you switched on since it opened.

A published app doesn't use these copies. It gets its own production database, the same sign-in and the secrets you pick when you publish. See [Production database and sign-in](/publish/production-data).

## Run servers the Preview can reach

The [Preview](/workspace/preview) shows any server on the machine that listens on a port and serves a page at `/`. Two rules decide whether yours shows up, and the agent follows both for you.

| Rule | Why |
| --- | --- |
| Bind `0.0.0.0`, never `127.0.0.1` | The Preview reaches the machine from outside, so a server bound to `127.0.0.1` can't be seen. For example `vite --host 0.0.0.0`, `next dev -H 0.0.0.0` or `uvicorn app:app --host 0.0.0.0`. Any port works. |
| Let the agent start it | The agent starts servers so they keep running after its turn ends, and through sleep and wake. A server started with a bare `&` or `nohup` can stop when the command that started it ends. |

When the agent starts a server, it waits until the server is listening and the Preview can reach it before it tells you it's running. If the server doesn't come up, the agent sees why, for example that it crashed, bound `127.0.0.1`, or found the port already taken, and fixes it.

Sessions run with full access, so the agent starts servers without asking. An older session left on another permission mode may ask you to approve the start, or to switch to **Full access**. See [What about permissions?](/chat/agents-and-models#what-about-permissions)

The agent switches Alpha's services on, publishes and reads production for you. You never type commands for these. Ask in plain words, and the matching tab opens when the service comes on.

| User sign-in for your app | "Add user sign-in to my app." | [Add sign-in to your app](/workspace/app-sign-in) |
| The app running in the Preview | "Start the app." | [Preview your app](/workspace/preview) |
| Your app online | "Publish this." | [Publish your app](/publish/publish-your-app) |

| A connected service | "Post each new booking to Slack." | [Integrations](/integrations/overview) |
| A key your app needs | "Take payments with Stripe." | [Secrets](/secrets) |
| An MCP server | "Install the Linear MCP server." | [MCP servers](/integrations/mcp-servers) |
| A reusable skill | "Save this workflow as a skill." | [Skills](/skills/overview) |
| A setup to start sessions from | "Save this environment as a setup." | [Setups](/sessions/setups) |

## Find logs and work within the limits

These are the places to look when something on the machine misbehaves, and the few things it can't do.

| Topic | What to know |
| --- | --- |
| A server's output | The server logs in the [Preview](/workspace/preview#read-the-logs), or ask the agent to read them |
| PostgreSQL's own log | `/var/log/postgresql/postgresql-16-main.log` |
| A setup's boot script | If it fails, a note in the transcript says where its output is. Ask the agent to read it. See [Keep a setup current](/sessions/setups#keep-a-setup-current). |
| Disk | {disk} per machine. Writes fail once it's full, so delete build outputs or large files. See [Limits](/reference/limits). |
| `mount` and FUSE | Both fail, for the agent and in the Shell, even with `sudo`. Copy files into `/workspace` instead. |
| `crontab`, timers and `sleep` loops | Not reliable. They don't run while the machine sleeps, its clock jumps when it wakes, they run without your environment, and you can't see their runs. Ask for a [routine](/routines) instead. |
| Decks on a port | Never served. The Preview would show a file listing or one long page instead of slides, so the agent opens decks in the slide viewer. |

<Note>
If the agent can't publish, or your app can't reach your connected apps, that feature may not be turned on for your Alpha. Ask your admin.
</Note>
