<Badge>About 20 minutes</Badge>

This guide builds an AI agent end to end: you describe it in one message, read it on the **Agent** tab, run it on a real customer email, then test it against a set of written test cases and fix what fails. If you want a feature inside an app that calls a model, rather than a standalone agent, describe the app instead; [Build an AI agent](/agents/build-an-agent) explains where the line falls.

By the end of this guide you will have `harbor-triage`, an agent that reads a message sent to Harbor Sailing School, sorts it, and drafts a reply, with an eval run that shows it passing every test case.

## Before you start

- A session you own. Start one from the [home screen](/sessions/home-screen), or use an existing one such as "Harbor bookings".
- An OpenAI key saved as a [secret](/secrets) named `OPENAI_API_KEY`. Add it on the **Secrets** page (**Account menu → Secrets**, then **Add secret** under **Global**) so every session gets it, or in the session's **Secrets** tab. The agent's live runs and the eval's AI reviewer both read it.
- The **Agent builder** skill switched on. It is on by default; see [Skills that ship with Alpha](/skills/built-in-skills).

<Warning>
Every live run spends money on your key. That covers the agent's own proof while it is built, each message you send in **Try it**, and every test case in an eval run. Writing test cases and working out the cost of a run are free. Nothing in an eval runs until you press **Run evaluation**.
</Warning>

## Build and test the agent

<Steps>
  <Step title="Ask for the agent">
    Paste this into the composer and press <kbd>Enter</kbd>. Say "agent" in words: "sort our inbox every morning" is built as app code instead.

    <PromptCard label="Try this">

    ```text
    Build an AI agent called harbor-triage for Harbor Sailing School.
    It reads one customer message as text and returns:
    the category (booking change, cancellation or weather, refund, question),
    how urgent it is, a two-line note for staff, and a draft reply in a
    friendly, plain voice. It must never promise a refund; staff decide those.
    ```

    </PromptCard>

    Alpha will:

    1. Ask you two or three [questions](/chat/plan-mode#answer-the-agent’s-questions): the agent's shape first, then its inputs or framework if your message leaves them open.
    2. Write the agent as a folder in `/workspace/harbor-triage` and draw it on the **Agent** tab before it is finished.
    3. Test it, including one live run on your key.
    4. Ask once whether you want a page around it. This guide declines.

    The questions open one at a time in a dock above the composer, with "1 of 3" at the top, while a card titled **The agent has questions** waits in the transcript. Each question lists its recommended option first. This guide typed its own shape into the **Something else** row: "Classify first, then write the staff note and the reply side by side, then one step that combines them." Press **→** to go on, and on the last question **→** sends your answers ("Send answers"). **Skip** leaves one question to the agent, and **×** ("Skip all — let the agent decide") leaves them all.

    <Frame caption="The agent asks how it should receive emails before it writes anything.">
  <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/guides/agent-01-question.webp" alt="The question dock in the Harbor triage agent session, asking How should the first version receive Harbor's emails?, with Email text or JSON (Recommended), Local .eml files and Live mailbox, then Something else, Skip and an arrow button." />
</Frame>
  </Step>
  <Step title="Read the agent on the canvas">
    The **Agent** tab opens by itself each time the agent publishes. Read it top to bottom: the **Inputs** card is what the agent is given, each step card below it is one step with its model and its task, and the **Answer** card lists the fields it hands back. Steps that run together sit in one outline with a `parallel · 2` chip.

    Click any card to open its details beside the canvas: the step's **Instructions**, **Task**, **Returns** and **Model**, and **Defined in**, which opens the agent's definition at the field the card comes from. To change the agent, ask in the composer, for example `Add a critic step that checks the reply`. See [The Agent tab](/agents/agent-tab).

    <Frame caption="The Agent tab draws the agent: inputs, the triage step and the answer.">
  <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/guides/agent-02-canvas.webp" alt="The Agent tab of the Harbor triage agent session showing Harbor Sailing School Inbox Triage: an Inputs card with email and received_at, the Harbor triage step on gpt-6-luna, and an Answer card with category, reply_draft, reply_subject, staff_action and summary." />
</Frame>
  </Step>
  <Step title="Try it on a real message">
    Click **Try it** in the canvas toolbar ("Run the whole flow on your own input"). A chat titled **Try harbor-triage** opens beside the canvas, with one field for each input and a few **Start from a sample** cards the agent wrote. Hover a sample and click **Use**, or paste a real message such as `Hi, the forecast says 30 knots on Saturday. Is my 9am dinghy class still on? I can't do Sunday.` Then click **Run**.

    Each message runs the whole agent once, live, with no memory of earlier messages. Each step card on the canvas shows **Running**, then **Done**, as the run reaches it. The answer shows each field, with **Copy**, and **JSON** for fields that aren't plain text; hover your message for **Edit and run again**. If a run fails, the chat says "This run did not finish.", and **Ask the builder to look into it** sends the failure to the agent. See [Try your agent](/agents/try-it).

    <Frame caption="One live run: the answer card shows the category, urgency and reply.">
  <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/guides/agent-03-try.webp" alt="The Agent tab after a Try it run on a refund request. The canvas cards are marked Done, and the Try it panel's answer card shows Category refund, Urgency urgent and the reply subject Re: Cancel tomorrow and refund please." />
</Frame>
  </Step>
  <Step title="Set up evals and review the test cases">
    Once the agent is proved live and published, the transcript shows a **Test this agent with evals?** card with **Set up evals** and **Not now**. Click **Set up evals**, read the **How evals work** dialog, and confirm with **Set up evals**. The flask button in the canvas toolbar ("Not tested yet: set up evals") does the same.

    The agent writes test cases for free and posts an **Eval proposal** card, marked "not started", with its cost range: "Costs real money. About \$X to \$Y on your key." Click **Open eval setup**. The eval opens as a tab of its own in the workspace, **harbor-triage eval**, with three steps: **Test cases**, **Run** and **Results**.

    On **Test cases**, each test case is someone (a persona) asking the agent something in a situation (a scenario), such as an upset customer asking for a refund. The grid at the top shows **Scenarios**, **What's being tested** and **Personas**. Click a row to open it and edit **What the user asks** or **What it checks**, and star the ones that **Must pass**: "If this test case fails, the whole evaluation fails." Then click **Next: set up the run**. [Set up evals](/evals/set-up) explains the coverage grid.

    <Frame caption="Scenarios on the left, personas on the right, one test case for each pair.">
  <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/guides/agent-04-test-cases.webp" alt="The harbor-support eval tab on its Test cases step, with the Test cases, Run and Results steps, New eval and All evals at the top. A map fills the page: SCENARIOS on the left lists situations such as Routine booking, Routine cancellation, Routine refund, Imminent weather and General information, each with 2 tests; WHAT'S BEING TESTED in the middle shows Harbor Sailing School Inbox Triage with its inputs, its step and its output; and PERSONAS on the right lists First time student and Group organizer, each with 25 tests. The footer reads 50 test cases. Review them, then set up the run, with Next: set up the run." />
</Frame>
  </Step>
  <Step title="Run the evaluation with a spending limit">
    The **Run** step, headed **Set up the run**, shows how each answer is graded: an AI reviewer scores it on the **Quality metrics** and explains each score, and **Format checks** check its shape in code, instantly and for free. Leave **AI reviewer model** as it is unless you have a reason to change it.

    The **Estimated cost** card works out the price before anything runs. Type a cap into **Spending limit**: no new test case starts once the next one would pass it. Then click **Run evaluation**. The eval moves to **Results** and shows each test case as it runs, several at once, with a line such as "Running 3, grading 1 · 4 of 10 done". A line above the eval shows what it has spent so far. The run keeps going if you close the tab; **Pause** and **Stop** are there if you need them, and **Stop** asks first (**Stop now** or **Keep going**). See [Run an evaluation](/evals/run).

    <Frame caption="The price is worked out first, and the limit caps what the run can spend.">
  <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/guides/agent-05-run.webp" alt="The Run step of the harbor-support eval: what's tested, the AI reviewer model, the quality metrics, and ESTIMATED COST About $0.10 with a Spending limit field and the Run evaluation button." />
</Frame>
  </Step>
  <Step title="Fix a failure with Alpha and run again">
    If the run fails, for example because a must-pass test case failed, the verdict reads **Not ready yet**. Its heading quotes what the first failed case checks, such as "Never promise a refund before staff review it.", then says which test case the agent didn't do it in. Click the case to read the agent's answer and the reviewer's reasoning.

    Click **Fix with Alpha**. The agent reads the failed cases together and proposes one change, to the agent or to a test case that checks the wrong thing. It shows you the change and edits nothing until you say yes, and re-proves the agent after changing it. Then click **Run again**. When every test case passes, the verdict reads **Ready**, and **Approve as baseline** makes later runs compare against this one. To test something else later, such as edge cases, click **New eval** and give it a focus. See [Read results and fix failures](/evals/results).

    <Frame caption="The verdict shows what passed and what still fails, with Fix with Alpha one click away.">
  <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/guides/agent-06-results.webp" alt="The Results step of the harbor-support eval. A card reads Not ready yet, 17 must-pass cases failed, with the first failure explained and a Fix with Alpha button. The figures row shows PASS RATE 66%, 33 of 50 passed, FAILED 17, COST $0.0793 est. and DURATION 6m 50s over a green and red bar. Below, the Overview shows TEST CASES as numbered hexagons, green with a tick for passed and red with a cross for failed, then BY SCENARIO and BY PERSONA bars. Run again and Open the results page sit at the bottom." />
</Frame>

    <Check>
    Your agent is built, tried on a real message and passing its eval. The canvas's flask button now reads "Evals: 10 of 10 test cases passed. Open the results", with a green dot.
    </Check>
  </Step>
</Steps>

You described an agent, read it, ran it once by hand, then proved it against a written set of test cases and fixed what failed. Run the eval again after each change to the agent, so you can tell whether the change made it better or worse.

<Note>
If Alpha builds app code instead of an agent and no **Agent** tab appears, the **Agent builder** skill may be off for your sessions. Open it on the [Skills page](/skills/overview) and switch on **Installed in your sessions**.
</Note>
