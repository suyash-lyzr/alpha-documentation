Every session runs one coding agent, **Codex** or **Claude Code**, on a model you choose at a reasoning effort you set. Together they decide how the agent works and what each turn costs. To have the agent plan before it builds, see [Plan mode](/chat/plan-mode). To see what a session has spent, or to bill the work to your own plan, see [Usage, costs and your own plan](/account/usage-and-costs).

## Codex or Claude Code?

Codex is OpenAI's coding agent. Claude Code is Anthropic's coding agent. Both work in the session's machine, with the same workspace, Preview, database, skills, MCP servers and publishing. The differences are in how you talk to them.

| | Codex | Claude Code |
| --- | --- | --- |
| Mention a [skill](/skills/overview) | `$name` | `/name` |
| File `/init` writes for the agent | `AGENTS.md` | `CLAUDE.md` |
| A [steer](/chat/queue-and-steer) joins the turn | At the agent's next step | Once the action under way finishes |
| Suggested next prompts after a turn | No | Yes |
| Set effort with a command | No, use the effort chip | `/effort` |
| List the sub-agents it can hand work to | No | `/agents` |
| Session commands from skills, MCP prompts, `.claude/commands` and plugins | No | Yes, in the `/` menu |
| **ultracode** effort | No | On models that offer xhigh |
| Run on your own plan | ChatGPT | Claude (Pro or Max) |

<Tip>
**Not sure?** Keep the agent the home screen picks for you. You can try the other one in your next session.
</Tip>

## Pick the agent for a new session

You choose the agent on the [home screen](/sessions/home-screen), before the session exists. Click the model chip, or type `/harness`, and pick **Codex** or **Claude Code** on the switch at the top of the menu, above the model list. Each side shows the agent's mark and name. `/harness codex` and `/harness claude` switch without opening the menu, and a name it doesn't recognise gets "/harness takes codex or claude — not "x"."

An agent you can't use yet shows a warning dot, and hovering it says why, such as "Connect your Claude account to use it" (or ChatGPT). Picking it opens that sign-in instead, and once you're signed in, the agent is picked for you. If the agent you used last can't run for you right now, a line under the switch says which one runs instead, for example "Claude Code isn't available to you right now, so this prompt's session runs Codex."

Switching agents resets the model and effort to the new agent's defaults, because each agent has its own models. Plan mode carries over.

<Note>
If you don't see the agent switch, your Alpha offers only one agent, and every session runs that one.
</Note>

### Why can't I switch agents inside a session?

A session keeps its agent for life. Codex and Claude Code can't read each other's history, so a switch would quietly throw away everything the agent knows about your work. Inside a session the model chip's menu has no switch. The badge beside the session title names the agent, and its tooltip reads "This session runs Codex. A session keeps its agent for life — start a new one to use another." `/status` lists it as **Harness**.

{/* screenshot to capture: /images/chat/chat-harness-badge.png — The badge beside the title says which agent runs the session. */}

Typing `/harness` in a session gets "A session's agent is fixed when it is created — this one runs Codex. Start a new session (/new) to use another." To move the work, push it to GitHub and start a new session on the other agent with the same repository.

## Choose a model

The model chip comes right after **+** in the composer. It shows the agent's mark and the model in force, by name, such as "Opus 5.5". Click it, or type `/model`, to open the model list.

  <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/chat/chat-model-picker.webp" alt="The model menu open above a session's composer. The composer's bottom row shows the + button, the model chip GPT-6.1-Sol highlighted, the effort chip xhigh, Build and the send button." />
</Frame>

Each row shows the model's name and a short tag, such as "latest · workhorse". Hover a row to read the model's full description. Claude models show their version, for example "Opus 5.5". A check marks the model in force; before you pick one, that's the agent's default model. The list is the agent's own, so it can differ between Alphas and change over time. With Claude Code, the list can also depend on whether the session runs on [your own Claude plan](#run-on-your-own-plan).

| You want to | Do this |
| --- | --- |
| Switch model | Pick a row. In a Claude Code session you can also type a name, for example `/model opus`. |
| Go back to the model you started on | Pick its row. |
| Set the model for your next session | Pick it on the home screen. Alpha remembers the agent, model, effort and mode in this browser. |

Picking a model resets the effort to that model's default. Changes apply from your next message; a running turn keeps the model it started with. If Alpha refuses a change, the chip goes back and a banner says why.

In a Codex session, a new model sometimes can't pick up the agent's earlier history. The transcript then says "The previous conversation can't be resumed with the current model — starting a fresh agent session (workspace files are kept)." Restate anything the agent needs from earlier in the session.

## Set reasoning effort

Reasoning effort is how long the model thinks before it acts. More effort helps on hard problems and costs more tokens and time. The effort chip sits beside the model chip, with a gauge icon and the effort in force, such as **xhigh**. Click it to open the **Reasoning effort** list and pick another.

<Frame caption="The effort chip lists every effort the agent offers; the one in force is checked.">
  <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/chat/chat-effort-chip.webp" alt="A crop of the home composer with the effort chip, reading xhigh, open below it. Its list, headed Reasoning effort, holds low, medium, high, xhigh with a check, max and ultra." />
</Frame>

The list holds every effort the agent's models offer, so it looks the same whatever the model. Efforts the model in use doesn't offer are dimmed, and hovering one says so: "\{model\} doesn't offer \{effort\} effort". A check marks the effort in force.

| Effort | Use it for |
| --- | --- |
| low | Quick edits, renames, copy changes and questions about the code |
| medium | Everyday building |
| high, xhigh | Hard bugs, refactors across many files, unfamiliar codebases |
| max | The hardest problems, when a lower effort keeps getting it wrong |

Until you pick an effort, the chip shows the one the model runs at by default.

| Agent | Effort until you pick one |
| --- | --- |
| Codex | **xhigh**, unless your Alpha is set up with another |
| Claude Code | **medium** on Opus 5.5, Sonnet 5.5 and Haiku 5.5, **xhigh** on Opus 4.7, and **high** on other models |

Each model has its own ladder. A Codex model may list a top rung such as **ultra**, which is part of that ladder, not ultracode.

In Claude Code, `/effort high` sets the effort and `/effort auto` returns to the model's default. A level it doesn't take gets "/effort takes low, medium, high, xhigh, max or ultracode (or auto for the model's own) — not "x"." In Codex, use the effort chip; picking the model's row again also returns the effort to the model's default.

## When is ultracode worth it?

Ultracode is xhigh effort plus multi-agent workflows <Badge>Claude Code only</Badge>. For every substantive task, Claude writes a workflow that fans the work out to many agents in phases, then waits for them. It's the **ultracode** row at the end of the effort list, marked with a workflow icon, and it's dimmed on models without xhigh ("\{model\} doesn't offer ultracode"). You can also type `/effort ultracode`. The effort chip then reads "ultracode".

{/* screenshot to capture: /images/chat/chat-model-picker-ultracode.png — Ultracode ends the effort list, and hovering it says what it costs. */}

<Warning>
Ultracode multiplies cost. Hover its row to read: "Each substantive task runs as a workflow of many agents at once — expect several times the tokens, cost and time of xhigh. Stop a workflow from its card in the transcript." Turn it on for a large, parallel job, then pick another effort when it's done.
</Warning>

Use it for work that splits well, such as a migration across many modules or a broad codebase review. For a single bug, xhigh is usually enough and costs far less.

Each workflow appears as a Workflow card in the [transcript](/chat/transcript). The card's **Stop** stops that workflow alone; the composer's stop button stops the whole turn, workflows included. The [Usage dashboard](/account/usage-and-costs) records "ultracode" as the effort.

On a model without xhigh, ultracode can't take effect, and the effort list says so. Where your Claude account or organization turns workflows off, the session runs at xhigh without them, and the transcript says so. To ask for one workflow without changing effort, write the word "ultracode" in your message.

## What about permissions?

Every session runs with full access. The agent installs packages, runs servers and edits files without asking, because its machine is its own and nothing it does reaches your other sessions. There's no permissions chip, and `/permissions` gets "/permissions isn't offered — every session runs with full access."

Older sessions left on another mode show a permissions chip with a shield icon, so you can set them back.

| Chip reads | Codex | Claude Code |
| --- | --- | --- |
| full access | **Full access** (default) | **Full access** (default) |
| auto | **Auto (guardian)** | **Auto (Claude's classifier)** |
| workspace | **Workspace write**: no dev servers or Preview | **Workspace write** |
| read only | **Read only** | **Read only** |
| ask me | Not offered | **Ask me**: Claude asks before each edit or command that needs approval, and the turn waits for you |

Pick **Full access** and the chip disappears for good.

## Run on your own plan

By default the agent's work runs on your Alpha's own access to the models. Sign in with ChatGPT and Codex sessions bill to your ChatGPT plan, with your plan's models in the list. Sign in with Claude and Claude Code sessions bill to your Claude plan. Each session switches on its next message. [Usage, costs and your own plan](/account/usage-and-costs#who-pays-for-the-agent’s-work) walks through both sign-ins.
