<Badge>About 10 minutes</Badge>

This guide walks you through one full pass of Alpha: describe an app, watch the agent build it, change it by pointing at it, and publish it. You don't write any code. If you'd rather understand the moving parts first, read [How Alpha works](/get-started/how-alpha-works).

By the end of this guide you will have a booking page for a sailing school, live at its own `https://` address.

{/* screenshot to capture: /images/get-started/quickstart-00-result.png — The finished Harbor booking app, published and open at its own address. */}

## Before you start

- An Alpha account. Open <a href={appUrl}>{appUrl}</a> and sign in, or see [Your account](/account/your-account).
- Nothing to install. Every session gets its own machine in the cloud, so a browser is all you need.
- No GitHub. This app lives in the session; you can [connect GitHub](/github/connect) later.

<Warning>
Keep API keys out of your messages. Anything you type in the composer lands in the transcript. Save keys as [secrets](/secrets) instead, and the agent gets them as environment variables.
</Warning>

## Build and publish the app

<Steps>
  <Step title="Sign in and open the home screen">
    After you sign in, Alpha opens on the [home screen](/sessions/home-screen): a greeting, the composer and a row of suggestion chips. There is no session yet. Your first message creates one.

    <Frame caption="The home screen, with the Harbor prompt typed and ready to send.">

Below the composer are seven suggestion chips: Apps, Agents, Decks & docs, Images & video, Data, Automations and Research." />
    </Frame>
  </Step>
  <Step title="Describe the app">
    Paste this prompt into the composer and press <kbd>Enter</kbd>. It names an outcome and how to check it; [Prompt Alpha well](/get-started/prompting) explains why that matters.

    <PromptCard label="Try this">

    ```text
    Build a class-booking web app for Harbor Sailing School.
    Show this week's classes (Beginner Dinghy, Intermediate Keelboat, Sunset Sail) as cards with the day, time, instructor and seats left, each with a Book button.
    Booking asks for a name and email, takes one seat and shows a confirmation.
    Keep the data in memory for now.
    When it works, start it so I can see it in the Preview, and check that booking a class lowers its seats-left count.
    ```

    </PromptCard>

    Alpha will:

    1. Start a fresh machine for the session, usually in about a second.
    2. Write the app in the machine's `/workspace` folder.
    3. Start it on a port and check that booking works.
    4. Open the Preview beside the chat.
  </Step>
  <Step title="Watch it work">
    Your message appears at once, with a status line under it: "Starting a fresh machine…", then "Handing your prompt to the agent…". A seconds counter appears after three seconds. Once the agent has your prompt, the line shows a working word such as "Striking while hot…". [What happens when you start a session](/sessions/start-a-session) covers each phase.

    The agent's commands, file edits and thoughts fold into one line with a tally. Click its chevron to see each one, as described in [Follow the agent's work](/chat/transcript). When the app serves a page, the **Preview** tab opens by itself.
  </Step>
  <Step title="Check it at phone width">

    </Frame>
  </Step>
  <Step title="Point at something to change">
    Click **Select** in the Preview toolbar, then click the description on the **Beginner Dinghy** card. The element becomes a chip in the composer, showing its tag and its first words, so the agent knows exactly which element you mean. Type `Make this text larger on mobile` and press <kbd>Enter</kbd>. Press <kbd>Esc</kbd> to cancel a pick. [Point at and draw on your app](/workspace/point-and-draw) shows the other ways to point.

    </Frame>
  </Step>
  <Step title="Send a follow-up while it works">
    While the agent works, <kbd>Enter</kbd> **queues** your message: it runs as its own turn after the current one. <kbd>⌘ Enter</kbd> (Ctrl on Windows and Linux) **steers** instead: the message joins the running turn without stopping it. Try queueing `Show a "Full" label on classes with no seats left.` To swap which key does which, open **Account menu → Settings → New messages**. [Queue, steer or stop](/chat/queue-and-steer) has the details.
  </Step>
  <Step title="Publish the app">
    Wait for the agent to finish, then click **Publish** at the right of the workspace tabs. The **Publish to production** popover shows what will go live: **Serves**, **Database**, **Sign-in** and **Access**. Click **Publish**, which sends "Deploy this." to the agent.

    <Frame caption="The Publish to production popover, before anything is sent.">
      <img src="/images/get-started/quickstart-05-publish.png" alt="The Publish to production popover open below the Publish pill at the top right of the workspace, which follows the server.js tab, the + button and the GitHub and Share icons. Cancel and a white Publish button with a rocket icon sit at the bottom right. Behind the popover, code from server.js shows at the left and the files panel, with the public folder open, at the right." />
    </Frame>

    <Note>
    If you don't see **Publish** beside **Share**, publishing isn't turned on for your Alpha.
    </Note>
  </Step>
  <Step title="Name it and open the address">
    The agent asks for a name in a [question card](/chat/plan-mode). Pick its suggestion or type your own, such as `harbor-bookings`. The name is the start of the app's address, so it can't be changed later. The **Publish** tab opens and follows the rollout through **Export**, **Plan**, **Build**, **Publish** and **Live**. This usually takes 2 to 6 minutes. When the version card shows **Published**, click **Open** on the **Published URL** card.

    {/* screenshot to capture: /images/get-started/quickstart-06-live.png — The rollout finished: the app is live at its own address. */}

    <Check>
    Your app is live. Anyone with the address can open it, and it keeps running when your session sleeps.
    </Check>
  </Step>
</Steps>

## What happens when you close the tab?

The work carries on. The agent doesn't run in your browser, so the transcript is complete when you return. Once no Alpha tab of yours has been visible for {idlePark}, a session with nothing running goes to sleep. Opening it wakes it with every file and process as you left them. Your published app runs outside the session's machine, so it stays up either way. See [Sleep, wake and reset](/sessions/machines).

You have done the core Alpha loop: describe, watch, point, publish.
