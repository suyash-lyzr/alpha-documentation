<Badge>About 10 minutes</Badge>

This guide walks you through one full pass of Alpha: describe an app, watch the agent build it, change it by pointing at it, and publish it. You don't write any code. If you'd rather understand the moving parts first, read [How Alpha works](/get-started/how-alpha-works).

By the end of this guide you will have a booking page for a sailing school, live at its own `https://` address.

{/* screenshot to capture: /images/get-started/quickstart-00-result.png — The finished Harbor booking app, published and open at its own address. */}

## Before you start

- An Alpha account. Open <a href={appUrl}>{appUrl}</a> and sign in, or see [Your account](/account/your-account).
- Nothing to install. Every session gets its own machine in the cloud, so a browser is all you need.
- No GitHub. This app lives in the session; you can [connect GitHub](/github/connect) later.

<Warning>
Keep API keys out of your messages. Anything you type in the composer lands in the transcript. Save keys as [secrets](/secrets) instead, and the agent gets them as environment variables.
</Warning>

## Build and publish the app

<Steps>
  <Step title="Sign in and open the home screen">
    After you sign in, Alpha opens on the [home screen](/sessions/home-screen): a greeting, the composer and a row of suggestion chips. There is no session yet. Your first message creates one.

    Leave the composer's controls as they are. Along its bottom edge, **+** adds files, a machine, GitHub repos, a skill or a secret set, none of which this app needs; the model chip and the effort chip pick the model and how hard it reasons; and the chip at the right reads **Build**, so the agent builds straight away instead of planning first.

    <Frame caption="The home screen, with the Harbor prompt typed and ready to send.">
      <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/get-started/quickstart-01-home.webp" alt="The Alpha home screen in the light theme, with the sidebar collapsed and the theme switch at the top right. The composer under the greeting holds the prompt Build a class-booking web app for Harbor Sailing School, with this week's classes, seats left and a Book button, and start it so I can see it in the Preview. Its bottom row shows the + button, the model chip reading GPT-6.1-Sol, the effort chip reading xhigh, the Build chip and the send button, now lit. The suggestion chips Apps to Research sit below." />
    </Frame>
  </Step>
  <Step title="Describe the app">
    Paste this prompt into the composer and press <kbd>Enter</kbd>. It names an outcome and how to check it; [Prompt Alpha well](/get-started/prompting) explains why that matters.

    <PromptCard label="Try this">

    ```text
    Build a class-booking web app for Harbor Sailing School.
    Show this week's classes (Beginner Dinghy, Intermediate Keelboat, Sunset Sail) as cards with the day, time, instructor and seats left, each with a Book button.
    Booking asks for a name and email, takes one seat and shows a confirmation.
    Keep the data in memory for now.
    When it works, start it so I can see it in the Preview, and check that booking a class lowers its seats-left count.
    ```

    </PromptCard>

    Alpha will:

    1. Start a fresh machine for the session, usually in about a second.
    2. Write the app in the machine's `/workspace` folder.
    3. Start it on a port and check that booking works.
    4. Open the Preview beside the chat.
  </Step>
  <Step title="Watch it work">
    Your message appears at once, with a status line under it: "Starting a fresh machine…", then "Handing your prompt to the agent…". A seconds counter appears after three seconds. Once the agent has your prompt, the line shows a working word such as "Striking while hot…". [What happens when you start a session](/sessions/start-a-session) covers each phase.

    <Frame caption="A few seconds in: the agent has your prompt, and the working line shows it’s still going.">
      <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/get-started/quickstart-02-starting.webp" alt="A new session a few seconds after its first message, with the sidebar collapsed. The header shows the title Harbor Sailing Classes and a pill with the Codex mark reading codex, and at its right the +, GitHub, Share and files buttons. The message reads Make a simple one-page website for Harbor Sailing School that lists this week's classes with times and seats left, and show it in the Preview. Under it, the agent replies that it will build a clean, nautical page with a weekly class schedule, check it on desktop and mobile and open it in the Preview, then a folded row reads 2 commands, and the working line reads Striking while hot… with a 5s counter. The composer at the bottom shows Add a follow-up and a round stop button." />
    </Frame>

    The agent's commands, file edits and thoughts fold into one line with a tally. Click its chevron to see each one, as described in [Follow the agent's work](/chat/transcript). When the app serves a page, the **Preview** tab opens by itself.
  </Step>
  <Step title="Check it at phone width">
    In the Preview toolbar, choose the phone icon, **Mobile · 390px**. The frame narrows in place. If the device switch is hidden, drag the divider to widen the workspace. [Preview your app](/workspace/preview) covers the rest of the toolbar.

    <Frame caption="Mobile narrows the frame, and the app’s phone layout takes over.">
      <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/workspace/preview-mobile.webp" alt="The Harbor bookings session with the Preview at phone width: the Preview toolbar with the Desktop, Tablet and Mobile buttons, Back, Forward, Reload, node · 3000 and Logs, then Draw, Select and Edit, with the Mobile button highlighted. The Harbor Sailing School app sits in a narrow frame in the middle of the workspace, showing the Harbor logo, This week's classes and My bookings, the headline Good days start on the water., the sailboat photo and the start of Make time for the tide." />
    </Frame>
  </Step>
  <Step title="Point at something to change">
    Click **Select** in the Preview toolbar, then click the description on the **Beginner Dinghy** card. The element becomes a chip in the composer, showing its tag and its first words, so the agent knows exactly which element you mean. Type `Make this text larger on mobile` and press <kbd>Enter</kbd>. Press <kbd>Esc</kbd> to cancel a pick. [Point at and draw on your app](/workspace/point-and-draw) shows the other ways to point.

    <Frame caption="The picked headline waits in the composer as a chip, above your request.">
      <img src="https://cdn.jsdelivr.net/gh/suyash-lyzr/alpha-documentation@271d124805a554c4fe200ef30c85667408772ff0/images/get-started/quickstart-04-select.webp" alt="The Harbor bookings session with the Preview on the right showing the Harbor Sailing School app, and Select highlighted in the toolbar. In the composer on the left, a chip reading h1 Good days start on the wa… sits above the typed request Make this headline smaller on phones, with the send button lit." />
    </Frame>
  </Step>
  <Step title="Send a follow-up while it works">
    While the agent works, <kbd>Enter</kbd> **queues** your message: it runs as its own turn after the current one. <kbd>⌘ Enter</kbd> (Ctrl on Windows and Linux) **steers** instead: the message joins the running turn without stopping it. Try queueing `Show a "Full" label on classes with no seats left.` To swap which key does which, open **Account menu → Settings → New messages**. [Queue, steer or stop](/chat/queue-and-steer) has the details.
  </Step>
  <Step title="Publish the app">
    Wait for the agent to finish, and bring the **Preview** tab to the front. Then click **Publish** at the right of the workspace tabs. While the agent is still working, the pill is greyed out ("The agent is busy — ask once it is done"). With a file's tab in front, the same spot reads **Publish as artifact**, which keeps that one file instead; see [Artifacts](/artifacts).

    The **Publish to production** popover shows what will go live: **Serves**, **Database**, **Sign-in** and **Access**. Click **Publish**, which sends "Deploy this." to the agent.

    <Note>
    If you don't see **Publish** beside **Share**, publishing isn't turned on for your Alpha.
    </Note>
  </Step>
  <Step title="Name it and open the address">
    The agent asks for a name in the question dock above the composer (see [Answer the agent's questions](/chat/plan-mode#answer-the-agent’s-questions)). Pick its suggestion, or type your own, such as `harbor-bookings`, in the **Something else** row, then press **→**. The name is the start of the app's address, so it can't be changed later. The **Publish** tab opens and follows the rollout through **Export**, **Plan**, **Build**, **Publish** and **Live**. This usually takes 2 to 6 minutes, and the agent replies with the address when it's done. When the status pill beside the app's name reads **live**, click **Open** beside the address.

    {/* screenshot to capture: /images/get-started/quickstart-06-live.png — The rollout finished: the app is live at its own address. */}

    <Check>
    Your app is live. Anyone with the address can open it, and it keeps running when your session sleeps.
    </Check>
  </Step>
</Steps>

## What happens when you close the tab?

The work carries on. The agent doesn't run in your browser, so the transcript is complete when you return. Once no Alpha tab of yours has been visible for {idlePark}, a session with nothing running goes to sleep. Opening it wakes it with every file and process as you left them. Your published app runs outside the session's machine, so it stays up either way. See [Sleep, wake and reset](/sessions/machines).

You have done the core Alpha loop: describe, watch, point, publish.
